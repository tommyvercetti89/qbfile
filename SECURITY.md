# Security Policy

## Supported Versions

We take the security of QBFile very seriously. The following versions of QBFile are currently supported with security updates:

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability within QBFile (such as cryptographic weaknesses, E2EE leaks, or remote crashes), please **DO NOT** open a public issue on GitHub. Public disclosure makes the vulnerability available to anyone and could put users at risk.

Instead, please report security vulnerabilities securely by following these steps:

1. Send an email to the project maintainer: **tommyvercetti89 [at] gmail [dot] com** (or your preferred security contact email).
2. Describe the vulnerability in detail, including steps to reproduce, potential impact, and a proof of concept (PoC) if available.
3. We will acknowledge receipt of your vulnerability report within **48 hours** and provide a detailed timeline for coordination and resolution.

## Our Security Commitment

* **Confidentiality**: We will keep all reports confidential until a patch is developed and a coordinated release is prepared.
* **Coordinated Disclosure**: We strive to address all critical vulnerabilities within **7 to 14 days** of initial report.
* **Credit**: We will gladly credit you in our `CHANGELOG.md` and release notes for your responsible disclosure!
